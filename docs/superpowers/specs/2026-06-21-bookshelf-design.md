# Bookshelf — Design Spec

**Date:** 2026-06-21
**Status:** Approved (pending written-spec review)
**Author:** Tekilian + Claude

## Goal

Add a **Bookshelf** section to the blog: a page that *looks like a real wooden bookshelf*, where each book stands as a colored spine and reveals its full cover on hover. Clicking a book opens its own review page. Fully trilingual (EN/KO/JA), consistent with the existing blog architecture.

## Decisions (from brainstorming)

| Question | Decision |
|----------|----------|
| What each book is / click target | A reading-list book → its own **review detail page** on the blog |
| i18n | **Fully translated** — `en/ko/ja` per book, linked by `ref` (like articles) |
| Shelf visual | **Packed spines** on wooden shelves (skeuomorphic bookcase) |
| Cover reveal | **Lift & float** — on hover the spine rises and its full cover floats above; click → review page |
| Shelf grouping | **By reading status**: Currently reading → Finished → Want to read (in that order) |
| Cover image source | **Local image per book**, at `assets/books/<ref>/cover.*` |
| Spine look | **Solid colored spine + vertical title text** (color set per-book or auto-derived) |
| Optional fields kept | **Star rating (1–5, half-steps)** only |
| Nav label | **Bookshelf** (translated for KO/JA) |

## Architecture

The feature reuses the blog's existing patterns end-to-end:
- A Jekyll **collection** (`_books`) mirrors `_articles` (per-language files, shared `ref`).
- Per-language **index pages** are generated by extending `_plugins/i18n_pages.rb`, exactly like `categories`/`tags`.
- Shelf markup lives in an **include** (`_includes/bookshelf-content.html`); the detail page is a **layout** (`_layouts/book.html`).
- All skeuomorphic styling lives in **`assets/css/main.css`** (served directly, no Tailwind rebuild), matching the existing `.nav-link` / dark-mode-override convention.
- Interaction is **CSS `:hover`** plus a small **vanilla JS** tap handler for touch devices (the site has no Alpine.js; only compiled Tailwind).

### Components & responsibilities

1. **`_books/<slug>/{en,ko,ja}.md`** — book content + metadata. One folder per book; three language files linked by `ref`.
2. **`_config.yml`** — registers the `books` collection (`output: true`, `permalink: /books/:path/`).
3. **`_plugins/i18n_pages.rb`** — extended to generate `/{lang}/bookshelf/` for each language and a top-level `/bookshelf/` (default lang), each rendering `{% include bookshelf-content.html %}`.
4. **`_includes/bookshelf-content.html`** — selects books for the current language, groups by `status`, renders the wooden bookcase with spines + hover-float covers + ratings. Hides empty shelves.
5. **`_layouts/book.html`** — single-book review page: cover, title, author, rating, status badge, review prose, EN/KO/JA switcher, back-to-shelf link.
6. **`_includes/nav.html`** — adds the Bookshelf nav link.
7. **`_data/translations/{en,ko,ja}.yml`** — `nav.bookshelf` + a `bookshelf:` strings block.
8. **`assets/css/main.css`** — `.bookcase`, `.shelf`, `.book-spine`, `.book-pop` (cover float), rating, and `.dark` overrides.
9. **`assets/books/<ref>/cover.*`** — cover images.
10. **`test/site_build_test.rb`** — extended assertions.

## Data model

### Book front matter

```yaml
---
title: "Atomic Habits"
author: "James Clear"
layout: book
status: finished          # reading | finished | wishlist
rating: 4.0               # optional; 0–5 in 0.5 steps. Omit for wishlist / unrated
spine_color: "#15803d"    # optional; auto-derived from ref if omitted
cover: ""                 # optional override; default convention assets/books/<ref>/cover.*
lang: en
ref: atomic-habits        # identical across the 3 language files
---
Review body in Markdown…
```

- **`status`** drives which shelf the book sits on. Exactly three values: `reading`, `finished`, `wishlist`.
- **`rating`** renders as star glyphs (full / half / empty) on the cover float and the detail page. Absent → no stars (shown as "—").
- **`ref`** links translations and also determines the cover folder and the default spine color.

### Cover convention

- Default path: `assets/books/<ref>/cover.jpg` (also accept `.png`/`.webp`).
- Optional `cover:` front-matter override (path relative to site root).
- **Fallback** when no cover file exists: render the float as a solid `spine_color` panel with the title + author text, so the shelf never shows a broken image.

### Spine appearance

- **Color:** `spine_color` if set; otherwise pick deterministically from a fixed palette (≈8 colors) using a stable index derived from `ref` (e.g. `ref | size | modulo: palette.size`), so each book keeps a consistent color without manual input.
- **Title:** printed vertically (`writing-mode: vertical-rl`); author in a smaller, dimmer line at the foot of the spine.
- **Height:** slightly varied per book (stable function of `ref`, e.g. 3 height buckets) for an organic packed-shelf look. Optional future override; not a front-matter field for v1.

## The bookshelf page (`bookshelf-content.html`)

```
Page title (translated)
┌─────────────────────────────────────────────┐  ← .bookcase (wood frame)
│ ● Currently reading (n)                       │
│   [spine][spine]                              │  hover → lift + float cover (★ rating)
│ ════════════════════ plank ══════════════════ │
│ ● Finished (n)                                │
│   [spine][spine][spine][spine][spine]         │
│ ════════════════════ plank ══════════════════ │
│ ● Want to read (n)                            │
│   [spine][spine][spine]                       │
│ ════════════════════ plank ══════════════════ │
└─────────────────────────────────────────────┘
```

- Liquid: `{% assign books = site.books | where: "lang", current_lang %}`, then partition by `status` into the three ordered shelves.
- Each spine is an `<a href="{{ book.url }}">` so the whole interaction is keyboard- and screen-reader-accessible and works without JS.
- Empty shelves are omitted entirely.
- Touch: a small JS handler makes the first tap reveal the cover and the second tap follow the link (desktop relies on `:hover`).

## The book review page (`book.html`)

Mirrors `post.html` conventions:
- Header: cover image (left/top), title (`h1`), author, star rating, status badge.
- Review body inside the same `prose prose-lg … rounded-[32px]` card used by posts.
- EN/KO/JA switcher reusing the post pattern: `site.books | where: "ref", page.ref`.
- hreflang tags already handled generically in `default.html` (keyed on `page.ref`) — verify it also covers books, extend if it only queries `site.articles`.
- "← Back to bookshelf" link to `/{lang}/bookshelf/`.

## Navigation & i18n

- `nav.html`: add Bookshelf link between Writing and About, using `t.nav.bookshelf` and the existing `.nav-link` style.
- Add to each `_data/translations/*.yml`:
  ```yaml
  nav:
    bookshelf: "Bookshelf"        # KO/JA translated
  bookshelf:
    title: "Bookshelf"
    currently_reading: "Currently reading"
    finished: "Finished"
    want_to_read: "Want to read"
    rating: "Rating"
    by: "by"
    back_to_shelf: "Back to bookshelf"
    empty: "No books on the shelf yet."
  ```

## Styling & dark mode

- New custom classes in `main.css`: `.bookcase` (wood gradient + side panels via `::before/::after`), `.shelf`, `.shelf-plank`, `.book-spine` (vertical text, inner shadows), `.book-pop` (floating cover, scale/opacity transition), rating/badge helpers.
- Light mode: warm browns; dark mode: cooler/darker wood + slightly stronger cover shadows, via `.dark .bookcase { … }` overrides alongside the existing GitHub-palette block.
- Respect `prefers-reduced-motion`: disable the lift/float transforms for users who opt out.

## Testing

Extend `test/site_build_test.rb`:
- `/en/bookshelf/`, `/ko/bookshelf/`, `/ja/bookshelf/`, and `/bookshelf/` exist in `_site`.
- A sample book detail page (e.g. `/books/<slug>/en/`) builds and contains the title + review text.
- Nav contains the Bookshelf link.
- A book with `status: reading` appears under the Currently-reading shelf markup.

A few sample books (with covers) will be added so the page is non-empty and testable.

## Out of scope (YAGNI)

Genre/tag filtering, external buy links, "date finished" sorting, reading-progress indicators, search. The data model stays clean enough to add any of these later.

## Implementation risks / notes

- **Jekyll collection static files:** images inside `_books/` are *not* reliably copied to `_site`; covers therefore live under `assets/books/` (already decided). Confirm during implementation.
- **Tailwind content scanning:** shelf visuals use custom `main.css` classes (not Tailwind utilities), so no `tailwind.config.js` change or `build:css` run is required for them. If any *new* Tailwind utility class is introduced in book templates, add `_books/**` to the `content` array and run `npm run build:css`.
- **`default.html` hreflang block** currently queries `site.articles`; confirm/extend so book pages emit correct hreflang.
